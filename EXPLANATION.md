# Разбор кода для защиты (тема «Типы данных в Go»)

Документ объясняет, **что** реализовано, **как** это работает и **какие типы данных Go**
при этом задействованы. Порядок — от базовых типов к композитным, как в отчёте.

---

## 1. Базовые типы

В структуре `Employee` ([employee.go](internal/employee/employee.go)) использованы
встроенные типы Go:

| Поле | Тип | Почему такой |
|------|-----|--------------|
| `ID` | `int` | целочисленный идентификатор; `int` — машинное слово (64 бита на нашей платформе), диапазона с запасом |
| `Name` | `string` | строка Go — неизменяемая последовательность байт в UTF-8; кириллица хранится корректно |
| `Department` | `Department` (на основе `string`) | см. §2 |
| `Salary` | `float64` | число с плавающей точкой двойной точности (IEEE-754) |

**Про `float64` и деньги.** Мы сознательно выбрали `float64` ради простоты, но у него
есть известная проблема: не все десятичные дроби представимы точно в двоичной системе
(`0.1 + 0.2 != 0.3`). Для реальных финансовых расчётов правильнее хранить сумму в копейках
целым числом — для этого в коде объявлен тип `Money int64` (§2), он показан как
альтернатива.

**Нулевые значения.** В Go у каждого типа есть нулевое значение: `int` → `0`,
`float64` → `0`, `string` → `""`, у структуры — структура со всеми нулевыми полями.
Поэтому в коде нет понятия «неинициализированная переменная»: `var e Employee` уже
валидное значение. Мы этим пользуемся — при ошибке конструктор возвращает `Employee{}`
(см. §3), а `AverageSalary` на пустой коллекции возвращает `0`, а не аварийно делит на ноль.

## 2. Пользовательские (именованные) типы

```go
type Department string
type Grade      int
type Money      int64
```

`type X Y` создаёт **новый тип** с тем же внутренним представлением, что и `Y`, но
считающийся компилятором отдельным типом. Это даёт:

1. **Безопасность типов.** Нельзя случайно передать произвольную строку туда, где ждут
   `Department`, — нужно явное преобразование `Department("Sales")`. Компилятор ловит ошибку
   на этапе сборки.
2. **Методы.** На свой тип можно навесить методы, чего нельзя сделать со встроенным `string`:
   ```go
   func (d Department) Valid() bool { ... }   // проверка, что отдел из известного списка
   func (m Money) String() string { ... }     // формат "1234.50 ₽"
   ```
3. **Читаемость.** По сигнатуре `FilterByDepartment(d Department)` сразу видно смысл аргумента.

### Константы и `iota`

```go
const (
    Engineering Department = "Engineering"
    Sales       Department = "Sales"
    HR          Department = "HR"
    Marketing   Department = "Marketing"
)

const (
    Junior Grade = iota // 0
    Middle              // 1
    Senior              // 2
)
```

- Отделы сделаны **строковыми константами** — так их удобно и выводить, и читать из JSON
  без таблицы соответствия.
- `Grade` показывает механизм `iota` — это счётчик внутри блока `const`, автоматически
  дающий `0, 1, 2, …`. Классический способ описать перечисление на числах.

Метод `Department.Valid()` через `switch` проверяет, что значение принадлежит known-множеству;
используется в конструкторе и при загрузке из файла.

## 3. Конструктор с валидацией и модель ошибок

```go
func New(id int, name string, dept Department, salary float64) (Employee, error)
```

В Go нет конструкторов языка — есть **соглашение**: функция `New…`, возвращающая
значение и `error`.

- `error` — это встроенный интерфейс (`interface { Error() string }`). Значение `nil`
  означает «ошибки нет».
- Функция возвращает **два значения**. Вызывающий обязан проверить ошибку:
  ```go
  e, err := employee.New(1, "Анна", employee.Sales, 90000)
  if err != nil { /* обработать */ }
  ```
- `errors.New("текст")` — простая ошибка; `fmt.Errorf("... %d", x)` — с подстановкой значений.

Что проверяет `New`:
1. `id > 0`;
2. имя не пустое (предварительно `strings.TrimSpace` убирает пробелы по краям —
   это тоже демонстрация работы со строками);
3. зарплата не отрицательная;
4. отдел входит в известный список (`dept.Valid()`).

При любой ошибке возвращается `Employee{}` (нулевая структура) + ненулевой `error`.
Вызывающий не должен использовать первое значение, если второе не `nil`.

## 4. Метод `ToString()` и интерфейс `fmt.Stringer`

```go
func (e Employee) ToString() string {
    return fmt.Sprintf("#%-4d %-20s | %-12s | %10.2f ₽",
        e.ID, e.Name, e.Department, e.Salary)
}

func (e Employee) String() string { return e.ToString() }
```

- **Метод** — функция с получателем `(e Employee)` перед именем: «этот метод принадлежит
  типу `Employee`». Получатель по значению (копия), потому что метод только читает поля.
- `ToString()` — как требует задание, «красивый вывод». Форматирование через `fmt.Sprintf`:
  - `%-4d` — целое, ширина ≥4, выравнивание влево;
  - `%-20s` — строка, ширина 20, влево;
  - `%10.2f` — дробное, ширина 10, 2 знака после точки.
  Фиксированная ширина полей → колонки выстраиваются ровно.
- `String()` реализует **стандартный интерфейс `fmt.Stringer`**:
  ```go
  type Stringer interface { String() string }
  ```
  Как только у типа есть метод `String() string`, функции `fmt.Println(e)` и `%v`
  автоматически используют его. Интерфейсы в Go «неявные» — не нужно писать
  `implements`, достаточно совпадения сигнатуры метода.

## 5. Композитный тип: срез структур `Employees`

```go
type Employees []Employee
```

### Что такое срез

Срез (`slice`) — это дескриптор из трёх полей: указатель на нижележащий массив,
длина (`len`) и ёмкость (`cap`). Сам срез — «окно» в массив.

- `append(s, x)` дописывает элемент; если ёмкости не хватило — выделяется новый массив
  большего размера и данные копируются. Поэтому результат `append` **обязательно**
  присваивают обратно: `s = append(s, x)`.
- Два среза могут указывать на один массив — тогда изменение через один видно через другой.
  Именно из-за этого фильтры (§7) возвращают **новый** срез, а не режут исходный.

### `Add` — получатель по указателю

```go
func (es *Employees) Add(e Employee) error {
    for _, existing := range *es {
        if existing.ID == e.ID {
            return fmt.Errorf("employees: duplicate id %d", e.ID)
        }
    }
    *es = append(*es, e)
    return nil
}
```

- Получатель `*Employees` (указатель), потому что метод **меняет сам срез** (растит его).
  Если бы получатель был по значению, `append` изменил бы копию, и снаружи ничего бы
  не поменялось.
- `*es` — разыменование: «сам срез, на который указывает `es`».
- Линейный поиск по `ID` обеспечивает **уникальность идентификаторов** — бизнес-правило
  коллекции.
- `range` даёт пару `(индекс, значение)`; индекс не нужен → `_` (в Go запрещены
  неиспользуемые локальные переменные).

### `AverageSalary` — защита от пустого среза

```go
func (es Employees) AverageSalary() float64 {
    if len(es) == 0 { return 0 }
    var sum float64
    for _, e := range es { sum += e.Salary }
    return sum / float64(len(es))
}
```

- Явная проверка `len(es) == 0` — иначе деление на ноль (`NaN`).
- `float64(len(es))` — **явное преобразование типа**. `len` возвращает `int`, а в Go нет
  неявных числовых преобразований: `int / int` дало бы целочисленное деление.
- Получатель по значению — метод ничего не меняет; копируется только дескриптор среза
  (3 слова), не данные.

## 6. Функции высшего порядка и обобщённая фильтрация

```go
func (es Employees) Filter(pred func(Employee) bool) Employees {
    result := make(Employees, 0, len(es))
    for _, e := range es {
        if pred(e) { result = append(result, e) }
    }
    return result
}
```

- В Go **функции — значения первого класса**: их можно передавать в аргументах.
  `pred func(Employee) bool` — параметр-функция (предикат).
- `make(Employees, 0, len(es))` — заранее выделяем ёмкость под худший случай, чтобы
  `append` не перевыделял память в цикле (оптимизация).
- Возвращается **новый срез** — исходная коллекция неизменна (проверяется тестом
  `TestFilter_NotMutatesSource`).

Конкретные фильтры — тонкие обёртки над `Filter` с **анонимными функциями (замыканиями)**:

```go
func (es Employees) FilterByDepartment(d Department) Employees {
    return es.Filter(func(e Employee) bool { return e.Department == d })
}

func (es Employees) FilterAboveAverage() Employees {
    avg := es.AverageSalary()                       // avg «захвачен» замыканием
    return es.Filter(func(e Employee) bool { return e.Salary > avg })
}
```

`func(e Employee) bool { return e.Salary > avg }` — замыкание: оно «помнит» переменную
`avg` из окружающей функции.

## 7. Сортировка через компаратор

```go
func (es Employees) SortBy(cmpFunc func(a, b Employee) int) Employees {
    result := slices.Clone(es)          // копия, чтобы не менять исходный порядок
    slices.SortFunc(result, cmpFunc)
    return result
}

func (es Employees) SortBySalaryDesc() Employees {
    return es.SortBy(func(a, b Employee) int {
        return cmp.Compare(b.Salary, a.Salary) // b,a местами => по убыванию
    })
}

func (es Employees) SortByName() Employees {
    return es.SortBy(func(a, b Employee) int {
        return strings.Compare(a.Name, b.Name)
    })
}
```

- `slices.SortFunc` (стандартный пакет `slices`, Go 1.21+) сортирует срез по функции
  сравнения. Контракт компаратора: вернуть **отрицательное**, если `a` идёт раньше `b`,
  **0** при равенстве, **положительное** иначе.
- `cmp.Compare` (пакет `cmp`) — готовый компаратор для упорядочиваемых типов.
  Перестановка аргументов `b, a` меняет направление на убывание.
- `slices.Clone` — сортируем копию, чтобы метод не имел побочного эффекта на исходные данные
  (та же логика, что у фильтров).

Это иллюстрация **параметрического полиморфизма**: один алгоритм сортировки, поведение
задаётся переданной функцией.

## 8. Композитный тип `map`: статистика по отделам

[stats.go](internal/employee/stats.go)

```go
type Stats struct { Count int; Sum, Avg, Min, Max float64 }

func (es Employees) DepartmentStats() map[Department]Stats {
    acc := make(map[Department]Stats)
    for _, e := range es {
        s, ok := acc[e.Department]
        if !ok { s = Stats{Min: e.Salary, Max: e.Salary} }
        s.Count++
        s.Sum += e.Salary
        if e.Salary < s.Min { s.Min = e.Salary }
        if e.Salary > s.Max { s.Max = e.Salary }
        acc[e.Department] = s
    }
    for d, s := range acc { s.Avg = s.Sum / float64(s.Count); acc[d] = s }
    return acc
}
```

- `map[Department]Stats` — **хеш-таблица**: ключ (отдел) → агрегат. Создаётся через `make`.
- `s, ok := acc[key]` — «comma-ok» форма: `ok` показывает, был ли ключ в map. Так мы
  отличаем «первого сотрудника отдела» (нужно инициализировать `Min`/`Max`) от последующих.
- **Важная деталь Go:** значение map нельзя изменять «на месте» (`acc[d].Count++` не
  компилируется), потому что индексирование map возвращает копию. Поэтому мы берём копию `s`,
  меняем её и **кладём обратно** `acc[e.Department] = s`.
- `Avg` считаем вторым проходом, когда для каждого отдела известны `Count` и `Sum`.

### Недетерминированный обход map

Порядок обхода `map` в Go намеренно случайный. Чтобы вывод был стабильным (и его можно было
показывать в отчёте), в `DepartmentStatsString` ключи сначала собираются в срез, сортируются
(`slices.Sort`), и только потом печатаются.

## 9. Вывод таблицей: `text/tabwriter`

```go
w := tabwriter.NewWriter(&sb, 0, 0, 2, ' ', 0)
fmt.Fprintln(w, "ID\tИМЯ\tОТДЕЛ\tЗАРПЛАТА")
...
w.Flush()
```

- `tabwriter` — стандартный пакет: принимает текст с `\t`-разделителями и при `Flush()`
  выравнивает столбцы по самой широкой ячейке.
- Пишем не в консоль напрямую, а в `strings.Builder` (`&sb`) — эффективный сборщик строк;
  метод `Table()` возвращает готовую строку, а печатает её уже вызывающий код. Это делает
  метод тестируемым и переиспользуемым.

## 10. Чтение данных из JSON

[loader.go](internal/employee/loader.go)

```go
type jsonEmployee struct {
    ID         int     `json:"id"`
    Name       string  `json:"name"`
    Department string  `json:"department"`
    Salary     float64 `json:"salary"`
}
```

- **Теги структуры** (`` `json:"id"` ``) — метаданные поля; пакет `encoding/json` по ним
  сопоставляет поля структуры с ключами JSON.
- `json.Unmarshal(data, &raw)` разбирает массив объектов в `[]jsonEmployee`.
- Затем каждая запись прогоняется через `New` (та же валидация, что и вручную) и `Add`
  (уникальность ID) — данные из файла проверяются так же строго.
- `fmt.Errorf("record %d: %w", i, err)` — оборачивание ошибки: `%w` сохраняет исходную
  ошибку в цепочке (можно потом достать через `errors.Unwrap`/`errors.Is`), а `%d`
  добавляет контекст — номер проблемной записи.

## 11. Демонстрационный сценарий `main`

[cmd/lab1/main.go](cmd/lab1/main.go) — пакет `main`, точка входа `func main()`.

Последовательно показывает всё, что просит задание:

1. печать всех сотрудников таблицей;
2. добавление новой записи и **ошибку при добавлении дубликата ID**;
3. фильтр по отделу;
4. фильтр «зарплата выше средней» + сортировка результата по убыванию

- `flag.String("data", …)` — разбор аргумента командной строки `-data`.
- `loadStaff` пытается прочитать JSON; если файла нет — использует встроенный набор
  (`employee.NewEmployees(...)`). Показывает обработку ситуации «файла нет».
- Метод-цепочки работают, потому что каждый фильтр/сортировка возвращает `Employees`,
  у которого снова есть все эти методы.

## 12. Тесты

[employee_test.go](internal/employee/employee_test.go),
[collection_test.go](internal/employee/collection_test.go)

- Файл `*_test.go`, функции `func TestXxx(t *testing.T)`, запуск `go test ./...`.
- Используется **табличный стиль** (table-driven): срез структур-случаев + один цикл
  `t.Run(tt.name, …)` прогоняет их все, каждый — как отдельный подтест.
- Что покрыто: валидация `New` (6 случаев), совпадение `ToString`/`String`, ошибка
  дубликата в `Add`, `AverageSalary` (в т.ч. пустая коллекция), неизменяемость исходного
  среза при фильтрации, корректность обоих фильтров, порядок в обеих сортировках,
  агрегаты `DepartmentStats` + инвариант «сумма по отделам = общая сумма».
- Дробные числа сравниваются с допуском `math.Abs(got-want) > 1e-9`, а не через `==`
  (особенность `float64`).

## 13. Сводка: какие типы данных продемонстрированы

| Категория | Где в коде |
|-----------|-----------|
| Встроенные: `int`, `string`, `float64`, `bool` | поля `Employee`, возвраты методов |
| Целочисленный `int64` | `type Money int64` |
| Именованные типы на основе базовых | `Department`, `Grade`, `Money` |
| Константы, `iota` | блоки `const` в `employee.go` |
| Структуры | `Employee`, `Stats`, `jsonEmployee` |
| Срез | `type Employees []Employee` |
| Ассоциативный массив | `map[Department]Stats` |
| Указатели | получатель `*Employees` в `Add` |
| Функциональный тип | параметр `pred func(Employee) bool`, компараторы |
| Интерфейсы | `error`, `fmt.Stringer` |
| Нулевые значения и их обработка | `Employee{}` при ошибке, `0` при пустой коллекции |
| Обобщённые функции стандартной библиотеки | `slices.SortFunc`, `slices.Clone`, `cmp.Compare` |
