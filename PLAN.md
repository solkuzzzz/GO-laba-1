# Лабораторная работа №1 «Типы данных в Go» — план реализации

## 1. Анализ задания

Нужно разработать программный прототип, демонстрирующий работу с типами данных Go,
с упором на **композитные типы и структуры**. Минимальный функционал:

1. Структура `Employee` с полями `ID`, `Name`, `Department`, `Salary`.
2. Функции:
   - добавление записи в срез структур;
   - фильтрация по отделу;
   - фильтрация «зарплата выше средней»;
   - сортировка (по одному или нескольким полям).
3. Метод `ToString()` для «красивого» вывода записи.
4. `main`, демонстрирующий все возможности на тестовых данных.

Дополнительно (творческая часть, повышает оценку):
- отдельный пакет с логикой + `main` в `cmd/`;
- таблица (`text/tabwriter`) для вывода списка сотрудников;
- статистика по отделам (`map[string]...`): количество, суммарный и средний оклад;
- unit-тесты (`go test`);
- чтение данных из JSON/CSV-файла;
- собственные типы (`type Money int64`, `type Department string`), константы-`iota`.

## 2. Целевая структура проекта

```
GO/
├── go.mod                     // module unik/lab1, go 1.22+
├── cmd/
│   └── lab1/
```

Если решено не усложнять — всё в одном пакете `main` (файлы `employee.go`, `collection.go`, `stats.go`, `main.go` в корне). План ниже описывает вариант с пакетами; для «плоского» варианта просто убрать `internal/` и импорты.

## 3. Проектные решения (согласовать до начала кодирования)

- Имя модуля: `unik/lab1` (заменить `test.go` — сейчас в нём невалидный `package go`).
- `Salary`: собственный тип `Money` (в копейках, `int64`) с методом форматирования, либо просто `float64`. **Рекомендация:** `float64` для простоты лабы, но упомянуть в отчёте про проблему точности.
- `Department`: `type Department string` + константы.
- Сортировка: через `slices.SortFunc` (Go 1.21+) с параметром-компаратором.
- Ошибки: `Add` возвращает `error` при дублировании `ID` / пустом `Name`.
- Стиль: `gofmt`, `go vet`, имена по `effective_go`; комментарии к экспортируемым сущностям.

## 4. Разделение работы между двумя разработчиками

### Разработчик A — ядро данных (пакет `employee`, тип и коллекция)

3. **Синхронизация 1:** merge ядра A. B перепроверяет B2 на реальной `AverageSalary`.
4. Параллельно: A7 (тесты ядра), B6–B8.
5. **Синхронизация 2:** сборка всего, `go test ./...`, ревью кода друг друга.

## 6. Что описать в отчёте (привязка к теме «Типы данных»)

- Базовые типы: `int` (ID), `string` (Name), `float64`/`int64` (Salary) — диапазоны, точность.
- Пользовательские типы на основе базовых: `type Department string`, `type Money int64`; методы на своих типах.
- Константы и `iota` для перечисления отделов.
- Композитные типы: структура `Employee`, срез `[]Employee`, `map[Department]Stats`.
- Ссылочная семантика срезов и `map`; почему фильтры возвращают новый срез.
- Интерфейс `fmt.Stringer` и метод `ToString()`.
- Дженерики (`Filter`, `slices.SortFunc`) как параметрический полиморфизм.
- Нулевые значения типов и их обработка (пустой срез → среднее 0).
